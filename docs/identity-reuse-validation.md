# 统一身份复用与 BB 登录指引（2026-10-23）

## 改动

桌面录制/开发配置只有本人会话，而 MCP 配置保留了本人已授权的登录恢复与邮件验证设置。两份目录此前独立，导致桌面在会话失效后反复要求人工登录。本次为用户明确授权的同账号目录建立加密关联；桌面自动连接和对话中的连接恢复均使用该关联。源目录的密码、邮箱配置和模型密钥保留在原处，只向桌面写回通过账号及域名检查的学校会话。

关联配置位于应用根目录 `shared-identity-link.dpapi`。它属于本机安装配置，不接受模型参数或任意网页提供的目录。恢复前后均核对当前账号、源账号及绑定摘要；锁定、账号变化、冷却和停止操作会中止恢复。未关联的安装继续使用原生官方登录流程。

BB、教务、图书馆等平台有各自的会话，统一身份用于自动建立这些会话。校方要求滑块、扫码或当前授权无法完成的验证时，界面显示验证类型、入口和具体操作。未知验证页面明确标注尚未识别，避免猜测验证码类型。头部提示随相关操作恢复成功清除，其他表单错误保留。

重新保存同账号身份时，Rust 和 Python 均保留原有的自动登录及邮箱验证设置；新会话身份仍默认不保存密码。

## 实现范围

- 原生官方登录、可见验证控件检测、会话落盘和桌面业务调度由 Rust 执行。
- 已授权 MCP 登录恢复通过固定 `identity_restore` 适配器复用现有 Python 提供方；完整自动邮件验证尚未迁移为纯 Rust。
- MCP 的恢复结果使用固定验证原因与操作指引。当前客户端仍须刷新连接以加载新源码。
- 安装包使用白名单业务引擎和全新暂存目录，附带三个可执行文件的 SHA-256 清单。
