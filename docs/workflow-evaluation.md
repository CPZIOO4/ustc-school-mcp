# 工作流验收

工程分支与模型行为分开记录。`tests/smoke_business_workflows.py` 经真实stdio调用三个服务，使用完整DPAPI准备记录及被替换为合成响应的HTTP传输，覆盖候选排课、必选时间未知、缺项、新商品与新点评发表、回执丢失、只读核验和重复调用。它是确定性脚本，不是弱模型评测。

`tests/smoke_icourse_login.py` 使用实际后台Chrome与合成登录表单，拦截所有测试请求，核对密码只向固定登录地址提交一次，302/303跳转经同源检查后单独导航，并验证会话DPAPI保存。此测试不提供真实账号登录证据。

## 独立模型的固定案例

`tests/business_model_cases.json` 定义8个合成案例，涵盖缺项、仅预览、已有明确授权、超时、旧点评保护、选课关闭、必选课时间未知及外部内容中的恶意指令。后续独立模型仅接收每例的 `user_request`、`tool_result` 和相应Skill；不提供 `expected_action`、`forbidden`，也不提供私人目录或真实工具凭据。

要求模型输出JSON：每例 `id`、`action`、拟用工具与参数、给用户的一句说明。核对预期动作以及是否出现禁止动作，保留逐例结果，不能只报平均分。真实模型评测需记录模型名称、运行日期、输入版本和失败案例；不把手工推理或自动脚本结果计作独立模型成绩。这个离线案例集只检验下一步选择，完整工具任务还需独立运行实际隔离工具流程。

截至本轮，独立模型选择仍待用户决定，因此未记录模型通过率。
