# 第四镜头：真实提醒与已登录作业入口

2026-10-22，Windows 原生 Tauri/WebView2 与 Rust 后端。

## 真实操作

在本人已授权的录制配置创建一条独立的「Lab1 复习（测试提醒）」日程，复用本人历史 Lab1 作业链接，设置在当前时间约20秒后提醒。实际等待后由后端定时检查触发应用内提醒；点击「查看」，进入对应日程，再确认提醒并点击原作业链接。

网页在原生应用顶部新标签中打开。核对页面标题「复查提交历史记录: Lab1」、本人账号、历史尝试时间和已提交附件，确认继承真实登录态。录制完成后取消测试日程，逐字段核对明天的两项正式日程保持不变。全程没有上传附件、开始新尝试或提交作业。

## 登录继承问题与修复

最初 BB 会话已过期，通过学校协调工具的既有统一身份恢复流程重新连接，并联网确认。随后仅将本人已授权的 BB 会话更新到录制配置，没有复制密码。

实测还发现原生网页标签使用永久文件记录「会话已导入」，但关闭最后一个网页或退出应用后，WebView2 会清除临时会话 Cookie。永久标记仍在，重新打开时跳过导入，导致作业页显示登录错误。

现将导入标记改为独立离线域上的 Secure、HttpOnly 会话 Cookie，与 WebView2 会话同生命周期。相同浏览器会话和版本内不重复覆盖网站状态；学校会话更新或新建浏览器会话时恢复应用绑定的有效会话。退出学校绑定或应用锁定仍沿用原有账号校验与标签清理。

验证包括4项原生宿主测试全部通过、关闭最后一个标签后重新打开同一作业、完全退出并重开原生应用后打开同一作业。两次真实页面都显示已登录提交记录。网站当前会话的状态保留、不同站点标记隔离与会话更新判断有单元测试覆盖。

## 视频

第四镜头10秒，拼接前35.5秒后共45.5秒。提醒卡片以共享形状衔接；点击作业链接时放大，随后展示真实原生网页标签和历史提交记录。输入、提醒和网页内容采用真实录制；卡片移动、镜头缩放、视觉聚焦和页面揭示为后期设计，较长等待做了剪辑。

输出为H.264 Main/yuv420p、AAC、1920×1080、60fps。私人素材与回执在`.local/video-shot4/`，不进入Git和安装包；输出目录为桌面「SchoolAgent_第四镜头_真实提醒」。本轮更新开发版宿主，没有另构建发布安装包。
