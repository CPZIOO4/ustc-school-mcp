# 日常使用体验验收

本轮以同学日常办理校园事务为主，现场演示为次。首页采用“对话＋常用操作”，保持简洁蓝白界面。介绍视频在真实使用流程稳定后另行制作。

## 验收原则

- 从具体使用任务出发，记录能复现的问题，修复后复验原路径。
- 区分静态布局、浏览器交互、真实 Tauri/WebView2、真实学校业务四种证据；前一种不能代替后一种。
- 自动测试使用独立临时目录、合成账号和本机模型服务，不导入个人会话，不产生学校写入或付费模型请求。
- 需本人登录、验证码或真实业务材料的环节，留待本人参与后验收；不以模拟结果宣称已经验证。
- 不对已经通过且未受后续修改影响的测试反复运行，不以用例数量衡量质量。

## 本轮重点

| 日常场景 | 关注的体验问题 | 验收方式 |
| --- | --- | --- |
| 第一次打开应用 | 能否看见登录、模型和常用入口，是否知道下一步 | 实际窗口与不同 CSS 视口检查 |
| 连续处理不同事务 | 草稿、材料、授权是否跟随正确对话 | 隔离 Chrome 和真实原生客户端 |
| 中文输入 | 选词确认是否误发送，输入是否被异步返回清掉 | 浏览器组合输入事件与慢响应测试 |
| 阅读长回答 | 刷新是否抢滚动位置，材料是否挤掉输入区 | 长消息、长文件名与窄窗口 |
| 模型出错或响应很慢 | 能否保留输入、查看错误、停止后续步骤并继续 | 本机模型故障与延迟服务 |
| 后台任务运行 | 课表、个人资料、任务历史能否读取 | 独立只读通道并发测试 |
| 回到旧任务 | 标题是否稳定、原回执是否保留、重开是否恢复 | 两轮对话与原生重启 |
| 键盘操作 | 焦点是否可见、历史菜单关闭后能否继续操作 | 窄窗键盘导航 |
| 安装包交付 | 新代码是否实际进入包、是否混入私人文件 | 白名单打包、包内摘要和真实原生冒烟 |

## 可重复运行的入口

在已安装项目依赖的 Windows 环境中：

```powershell
$env:SCHOOL_UX_BROWSER_TESTS = '1'
.venv/Scripts/python.exe -m unittest discover -s tests -p test_ux_interactions.py
.venv/Scripts/python.exe tests/smoke_daily_use.py --exe <完整的原生EXE路径>
.venv/Scripts/python.exe tests/smoke_native.py --exe <完整的原生EXE路径>
.venv/Scripts/python.exe tests/audit_native_package.py
```

`smoke_daily_use.py` 使用真实 WebView2 和 Rust IPC：检查首次使用、网站搜索、模型工具调用握手、跨对话草稿和附件、阅读位置、服务故障、停止慢响应、缓存课表、连续切页和重启保留。截图和 JSON 报告默认写入被 Git 忽略的 `.local/ux-20261018/native-daily/`。输入法测试是组合事件回归，不代表覆盖所有 Windows 第三方输入法。
