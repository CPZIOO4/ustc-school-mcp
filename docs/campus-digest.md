# 信息汇总、订阅和日历

Windows 应用左侧“信息中心”提供来源选择、预览、筛选、简报记录及日历下载。MCP 通过协调器 `workflow=digest` 或独立 `python -m school_mcp digest-serve` 使用。

## 当前范围

- 就业站：岗位、实习、科研助理、专场宣讲。岗位和宣讲来自官方网页实际使用的固定查询合同；未声称为学校公开文档 API。不提交简历或报名。
- 学院：数学、计算机、物理的通知和学术报告，支持列表/正文/分页。未接入其他学院。文字少于 500 字的图文详情，最多读取两张同站文章图片并在本机 OCR；每图响应至多 3 MiB、2500 万像素。OCR 时间单列为待核对候选，不自动用于日历或临期提醒；缺年份、多日期、星期冲突提示核对。支持已观察到的 WebPlus 站内跳转及 page.psp 页面，不跟随站外链接。
- 已有站点：教务处通知、一网通办待办、学工开放奖学金、个人当前借阅、青春科大报名中列表，以及用户选定的 BB 课程作业。不读取邮箱正文；邮箱仅作为已绑定的通知发件通道。
- 原文、发布时间、活动时间与截止时间分别保存，筛选命中原因可见。公开通知新旧混排，首次建立基线不群发历史；过期或不完整记录仍可在预览中人工核对。

## 快速配置与应用内验收

可选择“学术讲座、实习招聘、二者合并、课程作业”预设；课程作业还需勾选实际 BB 课程。一句话配置调用用户已连接模型，只提出来源、筛选和时间补丁，每项须有用户原话证据。模型不决定收件人、不启动订阅。预览后先应用到表单，再保存或开启；不合法的建议报错并保留原订阅。

“生成应用内试阅简报”仅将当前采集快照放到本机收件箱，明确标注试阅，不调用邮件，不消费正常日报的待推送变化。相同内容不重复生成。应用内接收无需绑定邮箱；邮箱仍是可选通道，仅在用户明确选择时开启。

## 后台行为

首次默认关闭。保存预览范围后手动采集，核对结果，再开启订阅。公开来源每轮最多 1–10 页、前 0–30 条详情；周期 15–1440 分钟，默认 60 分钟。其他站点也有分页上限；超出范围明确标为部分覆盖。无新增不发普通日报，已确认的临近截止事项单独提醒，每次截止时间最多一次。来源异常首次进入简报，不每轮轰炸；失败按来源逐步退避。

SQLite 内订阅、事项、报告均用当前 Windows 用户 DPAPI 加密，诊断日志不存正文/收件人/原始错误文本。最多保留 1500 个事项（90 天，每条摘要 1200 字）、1500 条待汇总变化、60 份简报；超限明确提示。每份简报最多展示 50 项并限制长度，完整正文通过原文链接查看；页面最多展示 100 条，标明截断。每个私人目录通过系统文件锁只运行一个后台脚本；失去锁的进程退出。不使用 AI 定时唤醒。

电脑需开机、联网且不睡眠。关闭浏览器页面不退出服务；重新启动应用恢复已启用订阅，漏过时段合并成一份补报。Windows 阻止独立后台进程时，桌面服务在自身进程内运行同一个固定采集循环，仍使用系统锁避免重复运行；退出应用服务会停止此模式。本版不注册操作系统开机任务，不保证主机重启后未打开应用就自动工作。独立 MCP 用户需重新启动已授权 worker，不使用进程内回退。暂停订阅后等待当前轮结束才可清理账号。

邮件推送需要用户明确指定收件人。逻辑简报先落盘，再准备并冻结原邮件草稿，SMTP 状态不明不新建草稿重发。用户修改订阅后，不恢复旧版本的待发草稿。发送服务器接受不代表最终送达。没有自动获取外部收件人或发送测试消息。

AI 整理为可选按钮，发送当前最多 50 条事项摘要（各最多 600 字）至用户配置模型；仅让模型返回已有 ID 的排序，输出事实仍来自原文记录。结果不合法或模型不可用时显示基础简报。后台采集/日报/日历不调用模型。

## 日历

事项从当前预览选择。课表直接读取教务官方周次到日期的映射与上课时刻，保留教学分组，不根据第一周或星期自行推算。导出 ICS 显示跳过原因；来源时间缺失时不声称课表完整。文件为快照，不是可远程订阅的 URL；稳定 UID 可供支持的日历软件更新条目，但重复导入是否合并取决于客户端。

功能验收与实测限制见 [验证记录](validation.md)。业务流程见 [信息中心 Skill](../.agents/skills/school-services/references/campus-digest.md)。
