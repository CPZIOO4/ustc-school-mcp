# Rust 全量迁移进度

2026-10-12 的有效决定：全面迁移业务核心到 Rust；不做速度对比；不把 Python 引擎作为最终架构。验收以功能、状态兼容、授权边界、错误恢复和真实安装包运行为准，不承诺零缺陷或未经测量的速度提升。

## 当前实际执行路径

`Tauri/Rust 宿主 → 临时 Python 应用协调层 → Rust school-core`

`school-core` 是独立编译的 Rust 程序，不调用 Python。通过匿名管道接收有大小上限的请求，不开放端口，不把凭据放入命令参数或日志。原生包强制提供该程序；核心出错时停止，不悄悄退回 Python 重做请求。遗留浏览器版/stdio MCP 暂时仍可使用原实现。

## 已保留的契约

- Windows 加密文件及聊天数据库双向可读；不导入原 MCP `.local`，不重新生成邮箱密码，不清除登录态。
- 模型请求不跟随重定向、不使用环境代理、不自动重试；响应和工具参数有大小上限，整批检查后才允许调度。
- 重复 JSON 键、非有限数、超出原生整数范围的整数参数直接拒绝，避免隐式改写数值。超大 ID 应使用字符串。
- 长对话保留全部用户原话及原任务回执；容量不足时停止，未知结果不转为再次提交许可。
- 慢模型请求与本地存储使用独立核心进程，避免网络等待阻塞本地状态读取。
- 公共站点读取、浏览器生命周期也各有独立管道；限速共享同一 SQLite，不因多个进程绕过冷却。只等待尚未发出的请求，不自动重发已经失败的 HTTP。
- 公共 HTTP 仅允许固定教务处/评课社区 HTTPS 域名，不携带 Cookie、不跟随重定向、不使用代理；解压后上限分别为 5/8 MiB。异常页、页码不符与明确零结果分开处理。
- BB/JW 等旧登录文件保持可读；新写入在身份可用时绑定账号。信任设备合并保留同账号 CAS Cookie，过期 Cookie 不会复活；独立评课/集市会话不混入学校凭据。读取过期记录不会删除磁盘原文件。
- Rust 只管理它创建的 Chrome 和临时目录，不接管用户浏览器、不开放任意命令接口。正常退出清理临时目录；Windows 核心强制退出时 Job Object 终止自有进程树，但强杀后的残留临时目录不保证同步删除。
- 财务仍只做准备预检，`safe_to_submit` 始终为 false；金额按整数分计算，不换算外币、不自动扣减疑似重复票据。
- 已运行的旧版引擎不会因新窗口启动被强制结束；原生宿主检查实际握手的核心版本，不把旧 Python 引擎误报为新 Rust 核心。
- 模型批量调用完整校验，只执行第一项；其他项明确记为未执行。停止后的迟到模型回答不触发新操作；已发出工具返回的回执先保存，再停下。
- 任务归属、目录权限、界面授权与上下文恢复是执行前的固定检查；模型参数不能提升许可。已执行写入及未知结果不可自动重放。
- 恢复提示由固定错误码生成，工具结果不能借 `next_step` 或 `recovery` 字段开启自动重试。

## 后续执行顺序

1. 继续迁移剩余登录站点、BB/青春科大 DOM 与业务 IO；保持工具参数、授权和回执格式。
2. 将应用协调与 IO 驱动移入原生宿主，减少跨语言调用；继续保留停止、授权和回执检查。
3. 迁移定时订阅、邮件及材料处理，移除全部 Python 运行时依赖。
4. 原生包不再包含 Python 后，分别验证 Windows、macOS、Linux；移动端需独立处理后台自动化、密钥存储和系统登录交互。

不需要再次审批迁移方向。只有缺少实际登录、设备环境或具体写入业务参数时，才需要用户补充。

## 固定工具目录维护

公开目录位于 `src/school_mcp/agent/catalog_data.json`，由 Rust 编译嵌入，兼容层也从这一资源读取流程清单。新增或调整站点工具时同步更新它，并运行 `tests/test_rust_catalog.py`：既有注册、参数 schema、说明和入口权限必须一致。随后重新构建核心和安装包；单独替换 JSON 不会改变已经编译的 Rust 权限目录。此资源纳入源码指纹和安装包白名单审计，不包含用户配置或登录态。

## 0.5.0 原生路径范围

`SCHOOL_NATIVE_CORE` 由原生宿主设置时，全部共享 `chrome_browser` 入口改由 Rust 启动 Chrome；教务处的通知列表、搜索、正文，以及评课社区的课程目录、搜索、教师页、课程详情、点评读取/搜索改由 Rust 完成。显式注入 `httpx.MockTransport` 的旧测试继续走兼容实现，不将这类测试冒充 Rust 网络验收；另有真实管道解析对照、Rust 本机 HTTP 测试和公开站点实测。

会话迁移覆盖 BB、教务、图书馆、财务、青春科大、评课社区、南七集市及共用校园入口。已有站点的登录流程仍需要 Python Playwright；本批没有将登录页面脚本、邮箱收发、订阅调度或整个应用后端称为已迁移。手机端和非 Windows 密钥存储也尚未完成。

## 0.6.0 业务迁移与兼容边界

原生应用的 BB/JW 查询使用独立认证 HTTP 核心管道。每个请求链新建 Cookie 容器，按域名、路径和有效期发送；响应中的 Cookie 仅在该请求链暂存，不混用账号、不返回客户端。只允许已适配的查询路径；POST 仅限教务只读 `open-turns`，其他提交仍经过既有业务授权和 DOM 提交流程。失败不重发，桥接层仅可等待尚未发送的限速请求。

教务的成绩遮蔽和汇总、课表、开课查询、必留课程、跨周次/校区冲突和有界排课搜索由 Rust 执行。BB 的提交计划仍使用原持久化锁和附件字节传输；Rust 校验准备时刻、期限、模板、目标、实际字段和新尝试附件摘要，回执未知不自动重交。

青春科大的原报名数据库保留，增设账号与活动的唯一防重表及触发器。不同关键词任务命中同一活动时也只允许一次提交；已提交或未知结果的门闩不释放。旧程序可读取原格式记录，但不得继续写入已经启用原生防重的任务库；已运行的旧 worker 也受到 SQLite 触发器约束。该限制不能通过清空记录或另建任务绕过。

Windows 计划任务不继承创建者环境，原生报名计划因此保存核心路径、版本及 SHA-256，并在 worker 访问学校或领取任务之前恢复和核验。核心缺失或文件改变时计划停止，需要在当前应用重新核对计划；不自动回退 Python 执行报名。这里只迁移了报名业务状态与决策，操作系统任务注册、等待和网页 DOM 仍为临时 Python IO。
