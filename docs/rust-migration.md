# Rust 全量迁移进度

2026-10-12 的有效决定：全面迁移业务核心到 Rust；不做速度对比；不把 Python 引擎作为最终架构。验收以功能、状态兼容、授权边界、错误恢复和真实安装包运行为准，不承诺零缺陷或未经测量的速度提升。

## 当前实际执行路径

`Tauri/Rust 宿主 → Rust school-core --desktop → Rust 登录、对话与应用入口`；尚未迁移的业务通过固定私有管道调用 Python 适配器。青春科大新原生计划另由操作系统直接启动 `school-core --young-worker`。

`school-core` 是独立编译的 Rust 程序。`--stdio` 通过匿名管道接收有大小上限的请求；`--desktop` 提供仅供本机宿主使用的认证回环 HTTP，并通过固定白名单调用临时 Python 业务适配器，不启动旧 Python HTTP 服务。凭据不放入命令参数或日志。原生包强制提供该程序；核心出错时停止，不悄悄退回 Python 重做请求。遗留浏览器版/stdio MCP 暂时仍可使用原实现。

## 已保留的契约

- Windows 加密文件及聊天数据库双向可读；不导入原 MCP `.local`，不重新生成邮箱密码，不清除登录态。
- 模型请求不跟随重定向、不使用环境代理、不自动重试；响应和工具参数有大小上限，整批检查后才允许调度。
- 重复 JSON 键、非有限数、超出原生整数范围的整数参数直接拒绝，避免隐式改写数值。超大 ID 应使用字符串。
- 长对话保留全部用户原话及原任务回执；容量不足时停止，未知结果不转为再次提交许可。
- 慢模型请求与本地存储使用独立核心进程，避免网络等待阻塞本地状态读取。
- 公共站点读取、浏览器生命周期也各有独立管道；限速共享同一 SQLite，不因多个进程绕过冷却。只等待尚未发出的请求，不自动重发已经失败的 HTTP。
- 公共 HTTP 仅允许固定教务处/评课社区 HTTPS 域名，不携带 Cookie、不跟随重定向、不使用代理；解压后上限分别为 5/8 MiB。异常页、页码不符与明确零结果分开处理。
- BB/JW 等旧登录文件保持可读；新写入在身份可用时绑定账号。信任设备合并保留同账号 CAS Cookie，过期 Cookie 不会复活；独立评课/集市会话不混入学校凭据。读取过期记录不会删除磁盘原文件。
- Rust 只管理它创建的 Chrome 和临时目录，不接管用户浏览器、不开放任意命令接口。正常退出清理临时目录；Windows 核心强制退出时 Job Object 终止自有进程树，但强杀后的残留临时目录不保证同步删除。
- 原生 DOM 只执行编译在适配器内的固定流程，网页请求通过站点约束和一次性写入门闩；模型不能提交任意 JavaScript 或 CDP 命令。BB、青春科大执行与本地状态使用不同核心管道。
- 应用上传检查目录范围、分块偏移、最终长度和摘要，拒绝链接及 Windows 重解析点。启动恢复只把运行中的聊天标为中断并保留关联回执，不自动继续提交。
- 财务仍只做准备预检，`safe_to_submit` 始终为 false；金额按整数分计算，不换算外币、不自动扣减疑似重复票据。
- 已运行的旧版引擎不会因新窗口启动被强制结束；原生宿主检查实际握手的核心版本，不把旧 Python 引擎误报为新 Rust 核心。
- 模型批量调用完整校验，只执行第一项；其他项明确记为未执行。停止后的迟到模型回答不触发新操作；已发出工具返回的回执先保存，再停下。
- 任务归属、目录权限、界面授权与上下文恢复是执行前的固定检查；模型参数不能提升许可。已执行写入及未知结果不可自动重放。
- 恢复提示由固定错误码生成，工具结果不能借 `next_step` 或 `recovery` 字段开启自动重试。

## 后续执行顺序

1. 迁移邮箱绑定、邮件验证码回退与其余站点业务 IO；保持工具参数、授权和回执格式。
2. 迁移固定适配器中的业务入口、个人资料/课表快照与学校模型平台页面，保留账号及回执检查。
3. 迁移定时订阅、其他后台脚本、邮件、日志及材料处理，移除全部 Python 运行时依赖。
4. 原生包不再包含 Python 后，分别验证 Windows、macOS、Linux；移动端需独立处理后台自动化、密钥存储和系统登录交互。

不需要再次审批迁移方向。只有缺少实际登录、设备环境或具体写入业务参数时，才需要用户补充。

## 固定工具目录维护

公开目录位于 `src/school_mcp/agent/catalog_data.json`，由 Rust 编译嵌入，兼容层也从这一资源读取流程清单。新增或调整站点工具时同步更新它，并运行 `tests/test_rust_catalog.py`：既有注册、参数 schema、说明和入口权限必须一致。随后重新构建核心和安装包；单独替换 JSON 不会改变已经编译的 Rust 权限目录。此资源纳入源码指纹和安装包白名单审计，不包含用户配置或登录态。

## 0.5.0 历史迁移范围

`SCHOOL_NATIVE_CORE` 由原生宿主设置时，全部共享 `chrome_browser` 入口改由 Rust 启动 Chrome；教务处的通知列表、搜索、正文，以及评课社区的课程目录、搜索、教师页、课程详情、点评读取/搜索改由 Rust 完成。显式注入 `httpx.MockTransport` 的旧测试继续走兼容实现，不将这类测试冒充 Rust 网络验收；另有真实管道解析对照、Rust 本机 HTTP 测试和公开站点实测。

会话迁移覆盖 BB、教务、图书馆、财务、青春科大、评课社区、南七集市及共用校园入口。已有站点的登录流程仍需要 Python Playwright；本批没有将登录页面脚本、邮箱收发、订阅调度或整个应用后端称为已迁移。手机端和非 Windows 密钥存储也尚未完成。

## 0.6.0 历史业务迁移与兼容边界

本节记录 0.6.0 当时的范围；BB/青春科大执行层与应用入口的当前状态见下节 0.7.0。

原生应用的 BB/JW 查询使用独立认证 HTTP 核心管道。每个请求链新建 Cookie 容器，按域名、路径和有效期发送；响应中的 Cookie 仅在该请求链暂存，不混用账号、不返回客户端。只允许已适配的查询路径；POST 仅限教务只读 `open-turns`，其他提交仍经过既有业务授权和 DOM 提交流程。失败不重发，桥接层仅可等待尚未发送的限速请求。

教务的成绩遮蔽和汇总、课表、开课查询、必留课程、跨周次/校区冲突和有界排课搜索由 Rust 执行。BB 的提交计划仍使用原持久化锁和附件字节传输；Rust 校验准备时刻、期限、模板、目标、实际字段和新尝试附件摘要，回执未知不自动重交。

青春科大的原报名数据库保留，增设账号与活动的唯一防重表及触发器。不同关键词任务命中同一活动时也只允许一次提交；已提交或未知结果的门闩不释放。旧程序可读取原格式记录，但不得继续写入已经启用原生防重的任务库；已运行的旧 worker 也受到 SQLite 触发器约束。该限制不能通过清空记录或另建任务绕过。

Windows 计划任务不继承创建者环境，原生报名计划因此保存核心路径、版本及 SHA-256，并在 worker 访问学校或领取任务之前恢复和核验。核心缺失或文件改变时计划停止，需要在当前应用重新核对计划；不自动回退 Python 执行报名。这里只迁移了报名业务状态与决策，操作系统任务注册、等待和网页 DOM 仍为临时 Python IO。

## 0.7.0 历史执行层与应用入口

共用 Rust CDP 驱动直接连接本程序创建的后台 Chrome，恢复受站点范围限制的会话，提供内部固定页面操作、响应读取及请求约束。BB 与青春科大业务代码使用该驱动，不再把这些 DOM 操作交给 Python Playwright。驱动没有可供模型调用的任意脚本、命令或网址入口；登录页面和其他尚未迁移的网页流程继续使用 Playwright。

应用入口的迁移覆盖应用数据目录初始化、模型配置及候选配置保存、模型列表/能力测试、候选配置启用、文件上传与路径校验、对话中断恢复。模型配置使用现有加密格式，候选只有通过能力测试后才替换现用配置；旧测试结果不能在配置已经改变后继续启用候选。材料按分块偏移写入并校验最终长度与摘要，限制在应用上传目录内，拒绝符号链接、Windows 重解析点和未完成上传。中断恢复在同一 SQLite 事务内保留原记录并标记中断；不会自动重放工具。Python 仍处理界面 HTTP 路由、通知、登录、实时业务授权与部分工具协调。

BB 原生执行层负责附件字节读取和冻结、已提交原文件的受限读取、实际文件上传、提交表单操作、原有加密任务与一次性目标锁，以及独立回执核验。保持标准个人作业、原文件重交、截止时间和模板边界；确认结果未知后只允许核验，不重新发送提交。工具入口与通用 BB 定时脚本调度尚未整体迁入 Rust。

青春科大的首页、活动列表/分页、详情、请求令牌捕获、唯一活动定位、报名确认及回执读取在 Rust 中执行。独立原生 worker 负责等待开放、轮询、共享限速与读失败退避；每次实际写请求前重新核对当前账号、授权条件和时间，再原子进入 `submitting`。取消监控会停止后续读取与提交；已进入提交或未知结果的任务不由取消动作撤回。受请求策略拒绝的浏览器不能继续使用，只有仍处于监控阶段的读取可在冷却后重新建立会话，写入不重放。

Windows 原生计划固定调用 `school-core --young-worker --schedule-id … --private-dir …`，参数不含凭据。Rust 负责计划文件、操作系统任务注册与核验，若任务注册无法核验则在停止对应系统任务后使用后台 Rust 等待进程；该降级不跨电脑重启。计划绑定核心路径、版本、SHA-256 和账号，执行前核验；普通核心调用还具有操作截止时间，后台监控由计划和活动时间控制。

0.6 旧原生计划应在当前应用重新复核。新代码不能因保留着旧核心文件就从旧 Python worker 继续解释原计划；旧入口收到原生计划会明确停止。保留原任务库、提交门闩与未知结果，不通过清空记录或另建任务绕过防重。原生 worker 需要重新认证时停止，由用户在账号页处理；本批没有把统一身份登录或邮箱验证码流程迁入 Rust。

本轮实际后台 Chrome 提交测试使用合成学校页面，验证固定 DOM、附件/请求约束、一次性写入及回执；没有借迁移验收执行真实学校提交或注册真实报名计划。Windows 安装包、当前 MCP 连接版本和真实账号登录须分别核验，不能互相替代。项目仍包含 Python 引擎，未完成 macOS/Linux/Android/iOS 适配，也未进行速度对比。

## 0.8.0 应用后端、对话执行与官方登录

原生宿主直接启动 Rust 主后端。它接收受限 HTTP 请求，管理运行状态、单操作互斥、授权确认、停止、账号锁定/清理、文件上传与下载、旧实例复用和宿主退出。启动握手同时核对核心版本及 `desktop_backend=rust`，不会把仍运行的旧 Python HTTP 服务认作新版。旧普通浏览器版和 stdio MCP 入口继续保留。

Rust 对话驱动读取加密配置与完整对话，构造模型上下文、发送模型请求、消费待确认记录，并依据固定执行器逐项调用工具。停止会取消未完成的模型等待；已经发出的业务调用仍等待回执，先保存再停止。公开提示词、流程说明和工具 schema 编译自 `desktop/chat_resources.json`，通过一致性测试核对。参数不能自行替换提示词、工具目录、API 设置或授予权限。

统一身份、BB、教务、青春科大、财务、图书馆、南七、评课及五个校园入口的人工登录使用 Rust CDP。官方页面由本人输入凭据；程序捕获学工号并核验站点状态，只加密保存会话、同账号信任设备和站点存储。后台恢复只尝试已有会话，需验证时返回账号页处理，不自动输入密码。账号冲突或保存前账号变化时停止，旧会话格式保留。登录管道支持开始、查询和停止，长时间人工验证不会堵住状态读取。

Python 临时适配器只有固定业务动作，无 HTTP 服务、模型对话循环或任意命令入口。它处理尚未迁移的工具执行、材料解析、订阅、校园资料、邮箱绑定及脱敏日志。状态/诊断与业务有独立持久管道，不将凭据放入参数；通信失败不自动重试已发业务。兼容业务执行时持有跨进程锁；断联会留下本机未知结果标记，阻止清理或切换账号，须核实原回执后人工处理，重启不会清除标记。保留 Python 引擎依赖，未完成全量迁移。

本轮测试使用合成页面、隔离账号和本机模型；真实身份认证、邮箱验证码、学校提交及跨平台实机支持不由这些测试证明。
