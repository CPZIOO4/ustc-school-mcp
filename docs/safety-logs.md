# 安全日志与故障反馈

在应用「模型与设置 → 安全日志与故障报告」查看错误、复制摘要、预览并导出 JSON 报告，或清理诊断记录。学校登录过期也可从本机应用入口使用。报告不会自动上传或发邮件，由使用者决定是否分享。

## 记录与保护

覆盖启动、API、模型、工具、连接/登录、后台脚本、文件处理及进度保存异常；重启发现未完成任务时记录中断。网页界面异常只记录固定错误类型。

固定字段只有随机错误编号、分类、服务/阶段、工具名称、最多八个项目代码位置、版本指纹、操作系统类型、时间、耗时、次数和结果确定性。不记录账号、凭据、验证码、URL、请求、业务 ID、对话、文件路径/名称/内容、截图、异常原文或局部变量。未在白名单中的字段直接丢弃，导出时再次限制字段。

诊断库是仅含上述字段的本机 SQLite 文件，不是私人数据库的副本，也不是防篡改审计。报告仍含使用时间和模块，分享前可检查预览。五分钟内同版本、类别、位置和结果类型的故障合并计数。读取/写入时清理 14 天前记录，最多 500 组，数据库限制 8 MiB；长期不运行时不另起清理进程。跨进程锁和事务防止并发覆盖。

## 恢复边界

区分尚未开始、查询失败、本机失败、结果未知和中断。结果未知先查原业务回执，日志不能解除防重复执行保护。清理日志不删除账号、聊天、附件、任务和原回执，也不删除已另存的报告。

日志写入失败仍返回错误编号并明确提示未保存，不重跑原业务。损坏/超限的诊断库可通过清理入口重置；磁盘满或无权限时不能保证持久保存。清理不承诺磁盘安全擦除。

新后台登录和报名进程不再追加原始 stdout/stderr 文本日志。此前已有的私人日志不自动删除，也不打进报告。强制终止进程不能保证留下当时堆栈；下次启动依据任务标记显示中断。解释器尚未启动的安装损坏不能由 Python 日志捕获。

## 应用无法打开时导出

Windows 应用无需打开浏览器或解密账号即可导出，目标文件必须不存在：

```powershell
.\USTC-School-Agent.exe --export-diagnostics "$env:USERPROFILE\Desktop\school-diagnostics.json"
```

自定义数据目录同时传原 `--data-dir`。源码入口为 `python -m school_mcp.desktop.server --data-dir <原目录> --export-diagnostics <新文件>`。

桌面日志在应用数据根目录的 `diagnostics`；独立 MCP 默认在其私人目录的 `diagnostics`。子进程继承桌面诊断目录。独立 MCP 可使用 `python -m school_mcp.safety_log --output <新报告.json>`；需要时加 `--directory <诊断目录>`。只读取诊断库，不打包相邻文件；不要输出到凭据或数据库位置。

## 验证

- `python -m unittest discover -s tests -p test_safety_log.py`：隐私金丝雀、损坏/超限、并发、保存失败、访问边界、清理及 MCP 回执。
- `python tests/smoke_safety_log.py`：后台 Chrome 实测限流、预览/复制/下载、强制中断恢复、不重试、离线导出和手机宽度。
- 加 `--exe dist/USTC-School-Agent/USTC-School-Agent.exe` 验证发行程序。使用隔离目录与合成数据，不操作学校记录。
