# 统一身份登录与设备信任

适用：用户明确要求登录统一身份或恢复学校认证状态。`identity` 流程由 BB 适配器承载，保存的认证状态供教务、BB、图书馆等适配器复用；不代表这些网站已经全部连接。

1. 协调入口选择 `identity` 流程。先调用 `school_bb_identity_status`，再用 `school_bb_identity_check_connection` 联网核验。状态文件中的历史 `connected` 不能替代本次联网结果。
2. 需要重新认证且已有用户登录授权时，调用 `school_bb_identity_reconnect`，参数为空。统一身份密码、邮箱客户端密码只使用本机凭据配置，不传入 MCP 参数、聊天、脚本参数或日志。
3. 返回 `started` 后，按建议间隔查询 `school_bb_identity_status`，不要重复启动。各站点登录共享互斥锁；如果其他登录正在运行，先查询它的进度。
4. 程序固定打开官方 CAS，优先恢复账号对应的加密会话；必要时提交一次已授权保存的身份凭据。学校要求二次验证时，等待异步页面加载，选择“邮件验证码”。只有用户已授权邮件回退、当前邮箱与授权绑定一致、页面密保邮箱能够匹配时才自动发码。
5. 发码前保存 INBOX 的 UIDVALIDITY 和 UID 边界。Coremail 未提供 UIDNEXT 时仅读取最高 UID 元数据。程序只查看边界之后的新邮件头，并在本地核对学校发件域、收件人、认证用途；只读正文、唯一提取验证码并直接提交，不将验证码返回模型或落盘。多个候选、邮箱变化、编号变化、读取失败、验证码被拒绝或超时都停止，不重新发码。
6. 图形/滑块或其他不支持的验证会报告具体原因并停止后台流程，不自动弹窗。只有用户明确选择人工验证时运行 `python -m school_mcp identity-login --headed`；不能绕过验证。
7. 成功必须到达官方个人中心，保存账号绑定的加密设备状态，再从磁盘读取到独立浏览器会话验证可复用。`connected` 仅指统一身份；接着执行用户原先目标网站的连接检查和查询。

学校可能让登录态到期或撤销设备信任；保存一次不保证永久免验证。更新 MCP 源码后须重载并核对 runtime_status，旧进程没有新入口。Rust 原生安装包的内嵌工具目录需重新构建后才包含新增流程。
