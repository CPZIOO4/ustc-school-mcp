# 青春科大项目的读取与条件分析

在用户要求找活动、比较项目、按条件筛选或准备报名时读取本文件。这里只负责读取、分析与办理前准备；报名执行未实现。用户的筛选要求不能被样本偏好替代。

## 实际样本与适用范围

2026-10-05 对当时账号“我要报名 → 报名中”的全部 6 页进行了读取，按项目 ID 去重得到 60 个顶层项目，并成功读取其 60 份详情。另读取全部 39 个系列项目的子项目列表，共 240 个不同子项目记录。未逐个打开 240 个子项目详情或附件，也未读取报名人员名单。

| 样本维度 | 本次结果 |
| --- | --- |
| 项目结构 | 21 个单次项目、39 个系列项目 |
| 项目形式 | 33 个现场参与、27 个提交作品 |
| 模块 | 德 3、智 20、体 8、美 26、劳 3 |
| 报名信息 | 5 个顶层项目标记需要填写报名信息；具体报名表未打开 |
| 单次项目标示学时 | 0.5–4 学时；不是已获得学时或所有活动的取值范围 |
| 系列子项目 | 240 条中，63 条状态文字为“报名中”，其余包括发布、报名已结束、学时公示和审核等状态 |

这是当前账号可见的报名中顶层目录，不是全校项目全集，也不包含对“已结束”“已收藏”“已关注”和独立马拉松入口的全面遍历。子项目状态不同，不能把 240 条都视作可报名。样本数量、时间、名额与状态不写成固定业务规则。

## 先读列表，再读详情，再确定具体场次

1. 进入“我要报名”后默认是“培养方案”。必须选择“报名中”，不能把默认页或被拦截的培养方案查询当成活动列表为空。
2. 记录筛选条件、总数与读取时间，按 UI 分页读取；等待每次列表响应和项目卡片更新后才翻页。按项目 ID 去重，核对已读取数与总数。此次响应中的 `current` 曾一直为 1，即使记录已翻页，因此不能单独依赖该字段判定页码或停止。
3. 对候选读取详情的基本信息、项目简介和组织方式/作品要求，不能只解析列表标题。列表有时没有报名截止时间，尤其系列项目；空值不等于永久开放。
4. 系列项目继续读取子项目，建立“系列 → 场次/期次/组别”关系，再核对当前场次详情。父项目的学期跨度不是必须全程参加的时间；父项目“举办次数上限”不是本人可累计报名次数或总学时。
5. 只有状态、报名窗口、资格、名额及必要资料都明确的具体项目/子项目，才能列为“符合已知报名条件”。仍不代表系统最终接受或学时已获批。

### 本轮确认的只读调用

接口路径相对 `https://young.ustc.edu.cn/login/wisdom-group-learning-bg`，是观察实际网页请求与前端调用后确认的读取路径，不是已注册的新 MCP 工具。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /mobile/item/enrolmentList` | 当前报名中列表；分页/过滤参数沿用实时网页请求，不猜参数或替换账号 |
| `GET /item/scItem/queryById` | 单次或系列项目详情，`id` 必须来自可见列表 |
| `GET /item/scItem/selectSignChirdItem` | 系列子项目列表，保留服务端原拼写 `Chird`；`id` 来自系列项目 |
| `POST /lib/scItemProgramme/selectProgramme` | 默认培养方案读取；并不是活动列表接口 |
| `POST /item/scItemPlace/list` | 详情页读取场地，正文也可能单独提供地点 |

使用后台 Chrome 的现有授权会话。仅在确认当前调用语义与上述相符后放行精确的只读路径，不批量放行 POST。认证标头只在内存中供原学校域名使用，不写入 Skill、运行输出或公开证据；禁止自动跟随认证请求到其他域名。报名、取消、关注、收藏、签到签退、作品提交和评价均不属于本流程。直接请求同样受此边界约束，不能靠换请求方式绕开浏览器拦截。

## 统一提取的信息

分析时为每个候选保留以下信息，并记录来源是列表、详情字段、正文、子项目还是外部尚待核对。未知值用“未说明/未读取”，不填零、不推断为无限制。

| 信息组 | 要提取的内容 | 分析意义 |
| --- | --- | --- |
| 身份与结构 | 名称、组织方、模块、形式、单次/系列、父项目与场次 | 防止同名、不同校区、不同期次混淆；系列不重复算作一次活动 |
| 报名窗口 | 报名开始、截止、当前状态、人数限制/已报名数、个人或团队 | 和举办时间分开；收藏人数不是报名人数；系列汇总不能推算场次余量 |
| 举办与投入 | 活动起止、具体场次、周期、校区地点、准备与交通时间 | 长周期作品征集不应被当成连续占用整段日程；也不能当成零耗时 |
| 资格 | 系统报名范围，以及正文中的年级、专业、社团/校队、基础要求 | 系统范围宽泛时仍需检查正文；不能仅凭标题或账号能看到就认为符合 |
| 学时 | 模块、标示学时、有效时长、学时认定条件、分组差异、上限 | 报名成功、完成参与、审核通过、学时到账是不同阶段 |
| 完成要求 | 到场、签到/签退、训练次数、阅读/创作、字数/时长、格式、证明、作品期限 | 判断实际需要做什么，而非只比较标示学时 |
| 附加步骤 | 外部网站报名、问卷、群内安排、线下交件、公开发布 | 标明平台外依赖；不擅自加群、发消息、注册或公开发布 |
| 报名资料与退出 | 是否需额外填写资料、重要承诺、费用、能否取消 | 标记未知/需用户提供的信息；未进入报名表时不声称完整掌握必填项 |
| 证据质量 | 来源、读取时间、缺失、矛盾、附件/图片是否已看 | 信息冲突不能静默修正；只在关键事实确定后作行动判断 |

字段名称须按接口区别处理：列表常见 `module_dictText`、`form_dictText`、`itemCategory_dictText`，详情对应 `moduleName`、`formName`、`itemCategoryName`。只取一种命名会把实际有值的模块或形式误判为空。详情中的 `serviceHour` 在本轮对应页面“学时”，`validHour` 对应“有效时长”；`hours` 在本轮顶层详情为空，不能因此宣称没有学时。即使两个字段本次相等，也保留其各自含义。

时间常见 `applySt/applyEt` 与 `st/et`；只在实际存在时记录 `attaEndTime` 等提交截止信息。正文、子项目或附件可能另有截止要求。原始数字状态及 `regOptions` 不能凭猜测译成业务含义，优先使用页面标签与字典文本。

## 从样本得到的核查规则

| 已见情况 | 以后怎样分析 |
| --- | --- |
| 系列活动详情显示学时“见各子项目”，有的系列当前子项目列表为空 | 报名对象落到场次；缺少场次时标记待发布/未返回，不能替父项目报名或按父项目估学时 |
| 女篮训练系统范围宽泛，但正文只允许校队成员 | 同时检查系统条件与正文条件；冲突时保留限制，不能自动当作合格 |
| 留学宣讲提供线上入口，却注明仅线下参与或签到给予学时 | 分开判断“能参加”和“能获学时”；线上会议标志也不能代替正文 |
| 乒乓球比赛标记“提交作品”，要求真实完赛后上传参赛记录 | 提交作品不等于纯线上活动；查作品证明背后的真实参与成本 |
| 乒乓球比赛与跑团活动要求另行在网站或群内报名 | 标明二课报名不足以完成参赛/参加；不能报告“一切已报名成功” |
| 同一乒乓球活动正文出现旧年份，与结构化时间不一致 | 展示冲突并标记待核实，不自行改成年份相同后继续办理 |
| 国庆升降旗体验标为“劳、提交作品”，实际要求到场参与并交带时间水印的合影 | 模块、参与方式和证明方式分开记录；劳学时不能直接等同其他系统的志愿服务时长 |
| 文学创作活动按组别给不同字数与学时；同一系列可能有不同难度场次 | 提取“组别 → 完成标准 → 学时”，不把最高学时套给所有参与者 |
| 小语种打卡要求每周多天学习且达到总时长；读书、配音有字数或录音时长门槛 | 用实际投入、节奏与可提供材料筛选，不能按题目看起来简单排序 |
| 游泳打卡要求本人当次已使用预约记录，且不可重复使用截图 | 记录真实性、当次性、关键字段要求；不代造参与证明、签到或训练记录 |
| 有项目要求原创、禁止 AI 生成作品或禁止 AI 检测格律 | 将具体项目要求保留为完成条件；辅助解释和检查不能被当成已经满足原创参与要求 |
| 有项目要求官网投稿、群内交音、线下交件，或在公开社交平台发布内容后再交证明 | 把外部步骤、公开发布和个人信息暴露作为选择因素；不默认用户愿意完成 |
| 现场活动可能要求签到和签退，而不是只进场 | 完成清单保留两端签到要求；代码字段为空不代表没有要求，必须读正文 |

以上是具体样本的现象，不能推广成所有活动的统一制度。未阅读的海报、附件、二维码、群公告仍是信息缺口，不能根据正文提及它们就宣称规则齐全。

## 将用户条件转为筛选结果

先分开用户的硬条件、偏好和操作范围。硬条件如目标模块、时间、校区、身份限制、是否接受作品或外部报名；偏好如主题兴趣、出行距离、投入量。只在影响选择时补问，已明确的条件无需重复确认。

逐项评估为“符合 / 不符合 / 未知”，未知不能自动通过。先排除不符合项，再按用户偏好比较；不要默认以学时最高或最容易完成为目标。若用户关心单位时间收益，投入信息不完整时只给范围和限制，不制造精确比值。

推荐结果可用：`项目及场次｜模块与条件性学时｜时间地点｜需要完成什么｜外部步骤｜符合/不符合理由｜待核实项`。没有合格项就说明缺口，不擅自放宽条件。报名执行尚未接入时，明确只完成筛选与准备；不得以此 Skill 声称已提交。
